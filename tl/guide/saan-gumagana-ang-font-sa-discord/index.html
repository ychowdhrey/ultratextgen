Saan Gumagana ang Fancy Fonts sa Discord

"Invalid username." Isang channel name na nawalan ng capitals. Isang nickname na nag-save nang maayos. Hindi inconsistent ang Discord — bawat field ay may trabaho, at bawat isa ay nagpapatupad ng magkakaibang rules. Narito ang buong permission map, para hindi ka na muling manghula.

Platform: Discord ⏱ 9 min basahin Ang Field Permission Matrix

Mga Dapat Tandaan

  • Ang unique @username ay tumatanggap lang ng lowercase a–z, 0–9, underscore at period. Mag-paste ka ng fancy font doon at makukuha mo ang "invalid username" — sa tuwina, by design.
  • Bawat presentation field — display name, server nickname, role, server at channel names, About Me — ay tumatanggap ng Unicode fonts at emoji nang walang tricks.
  • Nagre-render lang ang Markdown sa mensahe (plus ang basics sa About Me mo). Sa bawat name field, nakaupo lang ang mga asterisk.
  • May tunay na gastos ang styled names: hindi mahahanap ng Ctrl+K ang 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 sa pag-type ng "aesthetic," natitisod ang screen readers, at pwedeng magpakita ng boxes ang mga lumang Android.
Ang Pangunahing Ideya

Hindi Inconsistent ang Discord — May Trabaho ang Bawat Field

Ganito ang trial-and-error loop: ini-istayl mo ang name mo gamit ang generator, ipe-paste sa isang Discord field at maganda itong nagse-save. Ipe-paste mo ang parehong text sa ibang field at basta na lang tumatanggi ang Discord. Parehong characters, parehong account, magkasalungat na resulta. Pakiramdam ay pabigla-bigla.

Hindi. Malinis na nahahati sa dalawang pamilya ang mga field ng Discord. Ang identity fields ang inaasahan ng ibang system — mentions, friend requests, moderation logs, account recovery. Iisa lang: ang unique @username mo, at naka-lock ito sa napakaliit na character set para hindi ito kailanman ma-spoof, mali-type, o ma-render nang iba sa magkaibang phone. Ang presentation fields ang lahat ng tinitingnan ng mga tao — display names, nicknames, role names, server at channel names, ang About Me mo. Bukas na bukas ang mga iyon, kasi walang kritikal na dumadaan sa kanila.

Pag nakita mo na ang dalawang pamilya, sinasagot ng bawat "bakit ayaw i-save nito?" ang sarili nito. Hindi ka kailanman lumalaban sa bug; nagpe-paste ka lang ng presentation-grade na characters sa isang identity-grade na field. Pareho lang lagi ang solusyon: ilipat ang styling sa katabing field.

Ang #1 na Bitag

Username vs Display Name: Bakit Nangyayari ang "Invalid Username"

Itong iisang kalituhan ang gumagawa ng mas maraming failed attempt kaysa sa lahat ng iba pinagsama. Simula nang tinanggal ng Discord ang lumang four-digit discriminators, bawat account ay may dalawang pangalan, at sumusunod sila sa magkasalungat na rules:

  • Ang username — ang unique handle mo, ipinapakita na may @ sa profile mo. Pinapayagang characters: lowercase a–z, 0–9, _ at . — wala nang iba. Walang capital letters, walang spaces, at siguradong hindi 𝓬𝓾𝓻𝓼𝓲𝓿𝓮. Anumang labas sa set na iyon ay nagti-trigger ng "invalid username" error.
  • Ang display name — ang malaki at friendly na pangalang ipinapakita sa chat at sa profile mo. Tumatanggap ito ng spaces, capitals, emoji, at anumang Unicode font characters na kaya mong i-paste.

Kaya ang pattern na gumagana ay boring sa loob at styled sa labas:

Tinanggihan @𝕹𝖔𝖛𝖆 → "invalid username" ↓ Gumagana @nova_riot  +  display name 𝕹𝖔𝖛𝖆 ⚔

Sa loob ng server may pangatlong layer ka, ang server nickname, na nag-o-override sa display name mo para sa server na iyon lang — at kasing-permisibo lang nito. I-istayl ito bawat community: ୨୧ 𝒩𝑜𝓋𝒶 ୨୧ sa book club, 𝗡𝗢𝗩𝗔 sa esports server. Ang isang nickname generator ang bahala sa character-mapping para sa'yo.

Field Notes

Ang Kakaiba sa Channel Name: Auto-Lowercase, Auto-Hyphen

Tahimik na nire-rewrite ang text channel names pag-save: nilo-lowercase ang ordinaryong capitals at nagiging hyphens ang spaces, kaya ang General Chat ay lumalabas na #general-chat. Binabasa ito ng mga tao bilang "tinanggal ng Discord ang styling ko." Tingnan nang mabuti — ang plain na letra lang ang ginalaw nito.

Nai-type: GENERAL CHAT → na-save bilang #general-chat  ·  Nai-type: 𝗚𝗘𝗡𝗘𝗥𝗔𝗟 ✦ 𝗖𝗛𝗔𝗧 → na-save bilang #𝗚𝗘𝗡𝗘𝗥𝗔𝗟-✦-𝗖𝗛𝗔𝗧

Ang math-bold na 𝗚 ay hindi ordinaryong capital G — ibang Unicode character ito — kaya nilalaktawan ito ng lowercasing rule. Iyon ang loophole sa likod ng bawat server na nakita mong may capitalized at dekoradong channel lists. Dalawang footnote: hindi nino-normalize ang voice channels at categories (nabubuhay doon ang spaces at plain capitals), at ang category headers ang lugar kung saan pinakamaganda gumagana ang symbol dividers tulad ng ─── at ╭─.

Rendered Styling

Saan Gumagana ang Markdown — at Saan Ito Nakaupo Lang

Ang Markdown ang isa pang uri ng styling: mga symbol tulad ng **bold** na kino-convert ng Discord kapag nire-render nito ang isang mensahe. Ipinapakita ng matrix na maliit ang teritoryo nito — mensahe, plus ang basic formatting sa About Me mo. I-type ang **Nova** sa isang nickname field at nagse-save ang mga asterisk bilang literal characters, kasi ang name fields ay iniimbak at ipinapakita nang raw; walang renderer pass para i-convert ang mga ito.

Iyon ang praktikal na paghahati na dapat tandaan: rendered styling (Markdown) para sa sinasabi mo, pasted styling (Unicode) para sa itinatawag sa'yo. Ang buong mekanika — spoiler tags, code blocks, ang Nitro layer at ang klasikong "bakit ayaw mag-bold ng asterisk ko" na mali — ay nasa companion guide namin, Discord Text Formatting, Nilinaw.

Isang espesyal na kaso na dapat banggitin: colored text. Nabubuhay lang ito sa loob ng mensahe, sa pamamagitan lang ng ANSI code blocks, na may walong fixed colors at marupok na mobile support. Walang name field kahit saan sa Discord ang tumatanggap ng kulay. Ang buong teknik ay tinatalakay sa Discord colored text guide.

Mga Totoong Limitasyon

Kailan Hindi Mo Dapat I-istayl ang Isang Field (Kahit Kaya Mo)

"Tumatanggap ng Unicode" ay isang permiso, hindi rekomendasyon. Tatlong gastos ang kasama ng styled name, at sulit itong timbangin bago ka mag-commit:

Nasisira ang search

Ang Ctrl+K, member search at mention autocomplete ay tumutugma sa literal characters. Hindi kailanman mahahanap ng pag-type ng "aesthetic" ang 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 — walang iisang character silang pareho.

Natitisod ang screen readers

Pwedeng basahin ng assistive tech ang 𝕹𝖔𝖛𝖆 bilang "mathematical fraktur capital N…" o lubusang laktawan ito. Detalye sa accessibility guide.

Tofu sa lumang Android

Pwedeng lumabas na □□□□ ang mararangyang styles sa mga lumang device. Tingnan ang bakit lumalabas na boxes ang fonts para sa safe-style tiers.

Ang rule ko: i-istayl ang mga field na tinitingnan ng mga tao, panatilihing plain ang mga field na tina-type ng mga tao. Isang display name at category headers? I-istayl nang husto — maayos basahin ang bold, small caps at light symbols halos kahit saan. Isang abalang text channel na hinahanap ng mga miyembro araw-araw, isang role na palaging pini-ping ng mga mod, isang server name na gusto mong ma-discover? Panatilihing plain o halos plain ang mga iyon. At lubusang iwasan ang zalgo sa mga pangalan — maraming malalaking server ang awtomatikong nagmo-moderate nito, at ito ang style na pinakamalamang na sumira sa rendering.

Ang handle mo ay isang susi. Ang display name mo ay isang kostyum.
