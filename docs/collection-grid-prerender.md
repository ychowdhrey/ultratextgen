# Pre-rendering the collection grids

**Added 2026-09-10.**

## 1. What was wrong

898 pages render a **collection section**: a grid of ready-made combos, each
with a format picker (Inline / Vertical / Comma / Space / Bullet) and a
one-click **Copy Collection** button. On a `library/emoji-combos` or
`ms/library/simbol-ff` that section is not decoration — it is the payload, the
reason the page exists.

Every one of those 898 pages shipped it as an empty container:

```html
<h2>Ready-made sets for bios and dividers</h2>
<div id="aestheticCollectionsContainer"></div>
```

plus an inline `GROUPS` array and a call to `UltraTextGen.buildGrids()` on
`DOMContentLoaded`. A client that runs JavaScript sees the grids. A client that
does not sees an empty `<div>` under a heading.

CLAUDE.md's **Discovery Model** section states the cost directly: several search
and AI crawlers execute no JavaScript, and machine legibility is a distribution
feature rather than hygiene. The static footer and the pre-rendered library-hub
directories exist for exactly this reason; the collection grids had been left
out.

### The count, and a correction worth keeping

Measured 2026-09-10: **898** pages call `buildGrids`, **exactly one call each**,
the container always present, and **898 of 898 empty**.

An earlier read of the same population (recorded in CLAUDE.md's Accessibility
section) said "896 of 898 — only `library/bow-ribbon-symbols` and
`ja/library/ribon-kigou` pre-render theirs." Those two pages do have static
children inside the same container, but they are unrelated `.flag-row` symbol
tiles; `buildGrids` then appends its six sections underneath. **Nothing
pre-rendered its grids.** Counting "container has children" answered a
different question than the one being asked.

## 2. What changed

### The renderer became a string function

`buildGrids()` built its DOM with `document.createElement`. It now composes the
same markup as a string via `gridSectionsHTML()`, and inserts it with
`insertAdjacentHTML`. Behaviour is unchanged — verified below — and the reason
for the change is that a build-time generator can call a string function and
cannot call `createElement`.

That matters more than it sounds. The alternative was a second copy of the
markup inside the generator, which is the exact failure CLAUDE.md records for
the library-hub builders: two renderers over one source, drifting, with nothing
reporting the divergence. `scripts/lib/collection-grid-engine.js` slices the
marked regions out of `symbol-explorer.js` and evaluates them, the same
technique `scripts/lib/zalgo-engine.js` uses. It **throws** when a marker is
missing rather than falling back to a local copy.

Four marked regions, concatenated in file order:

| marker | what it carries |
|---|---|
| `@collection-grid-icons` | `COPY_ICON`, the inline SVG inside every button |
| `@collection-grid-strings` | `UI_STRINGS`, the per-locale button labels |
| `@collection-grid-iso` | `isoToFlag`, which 18 flag pages build `GROUPS` with |
| `@collection-grid` | `FORMATS`, `formatItems`, `escHtml`, `activeFormatsFor`, `gridSectionHTML`, `gridSectionsHTML` |

`buildGrids()` skips construction when the container already holds a
`.flag-grid-section`, so a pre-rendered page is not doubled and a page the
generator has not reached still works exactly as before.

### `GROUPS` is executed, not parsed

`scripts/prerender-collection-grids.js` runs each page's own inline script in a
VM against a capturing stub, and renders whatever `buildGrids` was actually
called with. That is deliberate: 18 flag pages build their groups by mapping
ISO codes through `isoToFlag()`, and a source-text parser would have to
reimplement that. Three `emoji-flags` pages also build their country tile grid
in the same script and call `getElementById(...).appendChild` first, so the DOM
stub returns a live chainable proxy rather than `null`.

A stub cannot smuggle in a call the browser would not make, because every
captured container id is checked against the real HTML and the splice asserts
the container's child count grew by exactly the number of groups. A page whose
container cannot be found is **reported, never written**.

### The block is spliced as text

The markers are HTML comments inside the container:

```html
<div id="aestheticCollectionsContainer">
  <!-- BEGIN prerendered collections: generated by scripts/prerender-collection-grids.js, do not edit -->
  <div class="mood-explainer flag-grid-section">…</div>
  …
  <!-- END prerendered collections -->
</div>
```

No cheerio round trip — for the reason `docs/source-attribution.md` §4 gives
about the JSON-LD fixer: re-serialising reformats every file it touches and
buries the real change in noise. Re-running replaces the block, so the pass is
idempotent (verified: a second run reports `898 already current, 0 updated`).

## 3. Gate interactions, each measured rather than assumed

| gate | effect | why |
|---|---|---|
| `check:translation-parity` | **no-op** | The fingerprint's `collectionSets` axis reads the `buildGrids` *call* in `<script>`, which did not move. The rendered markup adds no `<h2>` (it uses `<h3>`), no `.symbol-tile`, no `<table>`, no internal link. |
| `check:locale-translation` | **no-op after the `fi`/`ms` fix** — see §4 | Group names come from each page's own `GROUPS`, already in that page's language. |
| `check:editorial-footprint` | **excluded** | `.flag-grid-section` added to `DROP_SELECTORS` in `scripts/lib/editorial-corpus.js`. |
| `check:accessibility` | **no-op** | One container per page, so `preview-N` / `copyBtn-N` cannot collide; every button carries text. |
| `<lastmod>` | **advances once, correctly** | The grids are new visible content and new copy payloads on those pages. CLAUDE.md's own list of changes that legitimately advanced `lastmod` names "hubs pre-rendered". Nothing about what the hash *covers* changed, so no cache re-baseline is required. |

### Why the editorial corpus drops it

`scripts/lib/editorial-corpus.js` already harvests `name:` literals out of
inline scripts into the `ui` slot (`scriptTileNames`), and already drops
`button:not(.faq-question)`. So the group names were **already measured**, in
`ui`, from the script — and rendering them would count the same strings a second
time, in prose.

Worse, under the clean-on-touch em-dash rule it would make 898 pages answerable
for copy a hand edit cannot change: the next generator run overwrites it. That
is the identical argument `[data-static-directory]` carries, so the selector
sits beside it with the same reasoning written out.

## 4. `fi` and `ms` had no UI strings

`UI_STRINGS` is keyed by the 2-letter prefix of `<html lang>` and falls back to
`en`. It covered 29 locales and **not `fi` or `ms`** — so 5 pages
(`ms/library/simbol-y2k`, `simbol-roblox`, `simbol-ff`, `simbol-discord`,
`fi/library/horoskooppimerkit`) rendered English buttons under localised
headings. Invisible while the grids were JavaScript-only; pre-rendering would
have written that English into static HTML, where `check:locale-translation`
would correctly report it as introduced.

The root cause is the missing locale entry, so that is what was fixed.
**Every word is attested on this site's own pages in that language**, which is
the strongest evidence available without a native reviewer:

| key | `ms` | attested in | `fi` | attested in |
|---|---|---|---|---|
| copy verb | `Salin` / `Disalin` | `locales/ms.json`, 490 `ms/` pages | `Kopioi` / `Kopioitu` | `locales/fi.json`, 177 `fi/` pages |
| collection | `Koleksi` | 22 `ms/` uses | `kokoelma` | 2 `fi/` pages |
| format | `Format` / `salinan` | 18 / 2 `ms/` uses | `kopiointi…` + `muoto` | 24 / 7 `fi/` uses |
| inline | `Satu baris` | 7 `ms/` pages | `Rivi` | 6 `fi/` uses |
| vertical | `Menegak` | `Teks Menegak` in the `ms/` footer | `Pysty` | `pystyyn`, 8 `fi/` uses |
| comma | `Koma` | 4 `ms/` uses | `Pilkku` | `pilkkua`, `fi/` prose |
| space | `Ruang` | 10 `ms/` pages, incl. `ms/library/ruang-kosong` | `Välilyönti` | 13 `fi/` uses |
| bullet | `Senarai` | 1 `ms/` page | `Luettelo` | 1 `fi/` page |

**Two are compounds of attested stems rather than attested strings**, and are
flagged as such rather than presented as harvested: `Format Salinan` (ms) and
`Kopiointimuoto` (fi). Both are ordinary formations in their language from words
the site already uses; neither is an attested collocation.

## 5. Verification

**Behaviour, against the unmodified tree as a control.** A git worktree of the
pre-change commit was served alongside the working tree and both were driven in
headless Chromium. On `library/bow-ribbon-symbols` the container's serialised
HTML is **identical apart from the two HTML comments**, and the interaction
trace is identical on both: `sections=6`, a `vertical` tab click rewrites
`preview-0` from `୨୧ ⋆ 🎀 ⋆ ୨୧` to the newline-joined form and moves the
`active` class, and the Copy Collection button fires exactly one `copy_text`
event.

**Localisation**, on `ms/library/simbol-ff`: `label="Format Salinan"`,
`tabs=["Satu baris","Menegak","Koma","Ruang","Senarai"]`,
`copyBtn=" Salin Koleksi"`, no duplicate ids, and the comma tab reformats the
preview.

**The gate**, per CLAUDE.md's rule that adding a validator is not the same as
gating on it — four differently-shaped broken inputs, so it cannot be tuned to
one:

1. the pre-rendered block deleted from one page → **exit 1**;
2. one group's `<h3>` edited so the block no longer matches its own `GROUPS` →
   **exit 1**;
3. a page's `GROUPS` gaining a group without regenerating → **exit 1**;
4. the whole tree current → **exit 0**.

And that CI *gates* on it rather than merely running it:
`scripts/run-ci-gates.py --only collection_grids` returns 1 on a broken tree and
0 on a clean one.

## 6. Running it

```sh
npm run prerender:collection-grids              # report only
npm run prerender:collection-grids -- --write
npm run prerender:collection-grids -- --write --files path/index.html
npm run check:collection-grids                  # the diff-scoped gate
```

The generator is the fix for anything the gate reports. Do not hand-edit a
pre-rendered block: it is replaced on the next run, and the markup's single
owner is `gridSectionsHTML()` in `symbol-explorer.js`.

## 7. Left open: the country flag list is the same class, from a different mechanism

The 17 pages carrying `#countryFlagList` (`library/emoji-flags` and its 16
locale builds) hold a **195-entry `COUNTRIES` array** that is turned into tiles
in JavaScript. Measured rather than assumed: EN and `ar` carry **8** static
`.flag-row` tiles inside that container, `vi` carries **0**, and every one of
them carries all 195 in the script. So ~187 country tiles per page — the names
included, `Afghanistan` and `Zimbabwe` appear nowhere outside a `<script>` —
exist only after JavaScript runs.

That is a second instance of the same class, and deliberately outside this
change: the tiles are a different mechanism (`.flag-row` + `.flag-label` +
`data-symbol`, not `buildGrids`), so it wants its own generator, and unlike the
grids its output would be measured by `check:locale-translation` (`.flag-label`
is a visible tile label, which CLAUDE.md names as one of the three classes that
has shipped untranslated before). It is recorded here with its numbers so the
next pass does not have to re-derive them — and so the first read is not the
wrong one, as it was here: "entirely absent from static HTML" was the initial
phrasing, and 8 tiles on two of the pages are not absent.
