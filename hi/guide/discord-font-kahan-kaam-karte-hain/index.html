Discord में fancy fonts कहां काम करते हैं

"Invalid username." एक channel नाम जिसके capitals गायब हो गए। एक nickname जो बिना दिक्कत save हो गया। Discord असंगत नहीं है — हर field का एक काम है, और हर एक अलग नियम लागू करता है। यहां पूरा permission map है, ताकि फिर कभी अंदाज़ा न लगाना पड़े।

Platform: Discord ⏱ 9 मिनट पढ़ें Field Permission Matrix

मुख्य बातें

  • यूनिक @username सिर्फ lowercase a–z, 0–9, underscore और period स्वीकार करता है। वहां fancy font पेस्ट करें तो "invalid username" मिलता है — हर बार, जानबूझकर बनाई गई डिज़ाइन से।
  • हर presentation field — display name, server nickname, role, server और channel नाम, About Me — बिना किसी ट्रिक के Unicode fonts और emoji स्वीकार करता है।
  • Markdown सिर्फ messages में render होता है (साथ ही आपके About Me में बेसिक)। हर नाम field में asterisks बस वैसे ही पड़े रहते हैं।
  • स्टाइलिश नाम की असली कीमत होती है: Ctrl+K "aesthetic" टाइप करने पर 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 नहीं ढूंढ पाता, screen reader लड़खड़ाते हैं, और पुराने Android box दिखा सकते हैं।
मूल बात

Discord असंगत नहीं है — हर field का एक काम है

trial-and-error का चक्र ऐसा चलता है: आप जनरेटर से अपना नाम स्टाइल करते हैं, उसे एक Discord field में पेस्ट करते हैं और वह बढ़िया save हो जाता है। वही टेक्स्ट दूसरे field में पेस्ट करते हैं और Discord साफ मना कर देता है। वही कैरेक्टर, वही account, उलटे नतीजे। यह मनमाना लगता है।

है नहीं। Discord के fields साफ-साफ दो परिवारों में बंटते हैं। Identity fields वे हैं जिन पर दूसरे systems निर्भर करते हैं — mentions, friend requests, moderation logs, account recovery। ऐसा सिर्फ एक है: आपका यूनिक @username, और यह एक छोटे-से कैरेक्टर सेट तक बंधा है ताकि इसे कभी spoof न किया जा सके, गलत न टाइप किया जा सके, या अलग-अलग फोन पर अलग render न हो। Presentation fields वह सब है जो लोग देखते हैं — display names, nicknames, role नाम, server और channel नाम, आपका About Me। वे पूरी तरह खुले हैं, क्योंकि उनमें से कुछ भी ज़रूरी route नहीं होता।

एक बार दोनों परिवार दिख जाएं, तो हर "यह save क्यों नहीं होता?" अपने आप हल हो जाता है। आप कभी किसी bug से नहीं लड़ रहे; आप बस presentation-grade कैरेक्टर को identity-grade field में पेस्ट कर रहे हैं। हल हमेशा एक ही है: styling को एक field आगे खिसका दें।

#1 जाल

Username बनाम Display Name: "Invalid Username" क्यों होता है

यह अकेली गड़बड़ बाकी सबसे मिलाकर ज़्यादा फेल कोशिशें पैदा करती है। जब से Discord ने पुराने चार-अंकों वाले discriminator हटाए, हर account के दो नाम होते हैं, और वे उलटे नियम मानते हैं:

  • username — आपका यूनिक handle, profile में @ के साथ दिखता है। अनुमत कैरेक्टर: lowercase a–z, 0–9, _ और . — और कुछ नहीं। न capital letters, न spaces, और 𝓬𝓾𝓻𝓼𝓲𝓿𝓮 तो बिल्कुल नहीं। इस सेट से बाहर कुछ भी "invalid username" error देता है।
  • display name — chat और profile में दिखने वाला बड़ा दोस्ताना नाम। यह spaces, capitals, emoji और कोई भी Unicode font कैरेक्टर स्वीकार करता है जिसे आप पेस्ट कर सकें।

तो जो पैटर्न काम करता है वह अंदर से सादा और बाहर से स्टाइलिश होता है:

रिजेक्ट @𝕹𝖔𝖛𝖆 → "invalid username" ↓ काम करता है @nova_riot  +  display name 𝕹𝖔𝖛𝖆 ⚔

server के अंदर आपको एक तीसरी परत मिलती है, server nickname, जो सिर्फ उस server के लिए आपके display name को overwrite करती है — और यह भी उतनी ही खुली है। हर community के हिसाब से स्टाइल करें: book club में ୨୧ 𝒩𝑜𝓋𝒶 ୨୧, esports server में 𝗡𝗢𝗩𝗔। stylish नाम जनरेटर कैरेक्टर-mapping आपके लिए संभाल लेता है।

फील्ड नोट्स

Channel-नाम की खासियत: Auto-Lowercase, Auto-Hyphen

text channel नाम save होते ही चुपके से फिर से लिखे जाते हैं: सामान्य capitals lowercase हो जाते हैं और spaces hyphen बन जाते हैं, इसीलिए General Chat निकलता है #general-chat के रूप में। लोग इसे "Discord ने मेरी styling हटा दी" समझते हैं। गौर से देखें — इसने सिर्फ plain letters को छुआ।

टाइप किया: GENERAL CHAT → save हुआ #general-chat  ·  टाइप किया: 𝗚𝗘𝗡𝗘𝗥𝗔𝗟 ✦ 𝗖𝗛𝗔𝗧 → save हुआ #𝗚𝗘𝗡𝗘𝗥𝗔𝗟-✦-𝗖𝗛𝗔𝗧

math-bold 𝗚 सामान्य capital G नहीं है — यह एक अलग Unicode कैरेक्टर है — इसलिए lowercasing नियम इसे छोड़ देता है। हर उस server के पीछे यही loophole है जिसमें आपने capitalized, सजे हुए channel lists देखे हैं। दो footnotes: voice channels और categories बिल्कुल normalize नहीं होते (वहां spaces और plain capitals बचे रहते हैं), और category headers वहीं हैं जहां ─── और ╭─ जैसे symbol divider सबसे अच्छा काम करते हैं।

Rendered Styling

Markdown कहां काम करता है — और कहां बस पड़ा रहता है

Markdown styling का दूसरा तरीका है: **bold** जैसे symbol जिन्हें Discord तब बदलता है जब वह किसी message को render करता है। matrix दिखाती है कि इसका इलाका छोटा है — messages, साथ ही आपके About Me में बेसिक formatting। किसी nickname field में **Nova** टाइप करें और asterisks literal कैरेक्टर के रूप में save हो जाते हैं, क्योंकि नाम field raw store और दिखाए जाते हैं; उन्हें बदलने वाला कोई renderer pass नहीं होता।

याद रखने लायक व्यावहारिक बंटवारा यही है: जो आप कहते हैं उसके लिए rendered styling (Markdown), और जिससे आप बुलाए जाते हैं उसके लिए पेस्ट की गई styling (Unicode)। पूरी mechanics — spoiler tags, code blocks, Nitro परत और वो क्लासिक "मेरे asterisks bold क्यों नहीं होते" गलतियां — हमारे साथी गाइड में हैं, Discord टेक्स्ट फॉर्मेटिंग, आसान भाषा में।

एक खास मामला बताने लायक: colored text। यह सिर्फ messages के अंदर, सिर्फ ANSI code blocks के ज़रिए, आठ तय colors और कमज़ोर mobile support के साथ मौजूद है। Discord का कोई भी नाम field color स्वीकार नहीं करता।

किसी field को कब स्टाइल नहीं करना चाहिए (भले ही आप कर सकें)

"Unicode स्वीकार करता है" एक अनुमति है, सिफारिश नहीं। स्टाइलिश नाम के साथ तीन कीमतें आती हैं, और commit करने से पहले इन्हें तौलना ठीक रहता है:

Search टूटता है

Ctrl+K, member search और mention autocomplete literal कैरेक्टर से मैच करते हैं। "aesthetic" टाइप करने पर 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 कभी नहीं मिलेगा — इनमें एक भी कैरेक्टर सांझा नहीं।

Screen reader लड़खड़ाते हैं

Assistive tech 𝕹𝖔𝖛𝖆 को "mathematical fraktur capital N…" पढ़ सकती है या पूरी तरह छोड़ सकती है।

पुराने Android पर Tofu

सजीले styles पुराने devices पर □□□□ दिख सकते हैं। सुरक्षित रहने के लिए bold, italic या small caps जैसी बुनियादी स्टाइल चुनें।

मेरा नियम: जिन fields को लोग देखते हैं उन्हें स्टाइल करें, जिन fields को लोग टाइप करते हैं उन्हें plain रखें। display name और category headers? खुलकर स्टाइल करें — bold, small caps और हल्के symbol लगभग हर जगह ठीक पढ़े जाते हैं। एक व्यस्त text channel जिसे members रोज़ search करते हैं, एक role जिसे mods लगातार ping करते हैं, एक server नाम जिसे आप discoverable रखना चाहते हैं? उन्हें plain या लगभग plain रखें। और नामों में zalgo पूरी तरह छोड़ दें — कई बड़े servers इसे auto-moderate करते हैं, और यह वही style है जो rendering तोड़ने की सबसे ज़्यादा संभावना रखती है।

FAQ

अक्सर पूछे जाने वाले सवाल

क्योंकि यूनिक @username एक identity key है, display field नहीं। यह सिर्फ lowercase a–z, 0–9, underscore और period स्वीकार करता है — इसलिए Unicode font कैरेक्टर (या यहां तक कि एक सामान्य capital letter) पेस्ट करने पर Discord save करने से मना कर देता है। स्टाइलिश वर्ज़न को इसके बजाय अपने display name या server nickname में रखें; वे fields Unicode को पूरी तरह स्वीकार करते हैं।

हां। display names, server nicknames, role नाम, server नाम, channel नाम और आपका About Me — सब Unicode font कैरेक्टर और emoji स्वीकार करते हैं। स्टाइलिश टेक्स्ट बनाएं, फिर तैयार कैरेक्टर को field में पेस्ट करें — कुछ enable करने की ज़रूरत नहीं। bold, italic या small caps जैसी पढ़ने लायक स्टाइल को तरजीह दें ताकि पुराने devices और screen reader वाले members भी आपको पढ़ सकें।

text channel नाम normalize होते हैं: Discord सामान्य A–Z को lowercase कर देता है और spaces को hyphen में बदल देता है, इसलिए "General Chat" बन जाता है "general-chat"। Unicode font कैरेक्टर सामान्य letters नहीं हैं, इसलिए वे बिना छुए निकल जाते हैं — 𝗚𝗘𝗡𝗘𝗥𝗔𝗟 अपने caps बनाए रखता है क्योंकि वे math-bold कैरेक्टर हैं, A–Z नहीं। voice channel और category नाम इस normalization को छोड़ देते हैं और spaces व capitals बनाए रखते हैं।

हां। दोनों presentation fields हैं, इसलिए Unicode fonts, symbols और emoji बिना शिकायत save होते हैं, और स्टाइलिश hoisted role member sidebar में दिखता है। बदले में: search, mention autocomplete और कई moderation bots literal कैरेक्टर से मैच करते हैं, इसलिए भारी स्टाइल किया role नाम ढूंढना और टाइप करना मुश्किल हो जाता है।

हां — mentions स्टाइल किए कैरेक्टर से नहीं, आपके account से resolve होते हैं। आपका plain @username टाइप करने पर आप हमेशा मिल जाते हैं, और आपके नाम पर click करना या member list से चुनना भी काम करता है। जो टूटता है वह है display-name से autocomplete: "aesthetic" टाइप करने पर 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 मैच नहीं होगा, क्योंकि वे अलग कैरेक्टर हैं। इसीलिए Discord handle को plain रखता है: आप तक पहुंचने का यह पक्का तरीका है।
