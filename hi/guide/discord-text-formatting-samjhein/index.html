Discord टेक्स्ट फॉर्मेटिंग, आसान भाषा में

आपको "fonts" की समस्या नहीं है — आपको तीन-system की समस्या है। Discord बिल्कुल अलग-अलग कामों के लिए Markdown, Unicode कैरेक्टर और Nitro styles इस्तेमाल करता है। एक बार जान लें कि कौन-सा field कौन-सा system चलाता है, तो हर "यह काम क्यों नहीं करता?" अपने आप हल हो जाता है।

Platform में महारत ⏱ 8 मिनट पढ़ें 3-System मॉडल

मुख्य बातें

  • Discord के तीन बिना संबंध वाले टेक्स्ट system हैं: Markdown (messages), Unicode "fonts" (हर जगह नाम), और Nitro (paid display-name styles)।
  • **bold** जैसा Markdown सिर्फ messages में render होता है — यह username, nickname या server/channel नामों में कभी काम नहीं करता।
  • Unicode "fonts" हर नाम field में काम करते हैं पर कुछ devices पर box दिख सकते हैं और screen reader तोड़ देते हैं।
  • Nitro आपके display name पर असली color और effects जोड़ता है — पर server के अंदर आपका role color जीतता है और सिर्फ font दिखता है।
नज़रिया बदलें

यह fonts नहीं — तीन अलग system हैं

Discord का लगभग हर "मेरा टेक्स्ट काम क्यों नहीं करता" वाला सवाल तीन ऐसी चीज़ों को गड्डमड्ड करने से आता है जिनका आपस में कोई लेना-देना नहीं। Discord chat में आपको Markdown सिखाता है, इसलिए आप मान लेते हैं कि वही ट्रिक आपके नाम को भी स्टाइल कर देगी। नहीं करती — नाम पूरी तरह अलग system चलाते हैं।

यहां पूरा नक्शा एक ही फ्रेम में है। सीख लें कि हर field कौन-सा system इस्तेमाल करता है और फिर कभी हैरान नहीं होंगे।

System 1

Markdown — messages के लिए

Markdown वह formatting है जो Discord तब लगाता है जब वह आपका message दिखाता है। आप अपने शब्दों के इर्द-गिर्द symbol टाइप करते हैं और Discord उन्हें असली styling से बदल देता है।

  • **bold** → bold
  • *italic* → italic
  • ~~strikethrough~~ → strikethrough
  • __underline__ → underline
  • ||spoiler|| → click करने तक छिपा
  • > quote और `code`

message format करने का यही सही तरीका है — यह असली text रहता है, इसलिए searchable और accessible है। पेच वे दो गलतियां हैं जो इसे "काम न करने" वाला बना देती हैं:

bold नहीं होगा

** text ** — asterisks के अंदर space इसे रद्द कर देता है। **text** इस्तेमाल करें।

bold नहीं होगा

`code block` के अंदर backticks Markdown बंद कर देते हैं। styling को बाहर ले जाएं।

और सबसे बड़ी बात: Markdown username, nickname, server नाम या channel नाम में कुछ नहीं करता। वे messages नहीं हैं, इसलिए Discord उन पर कभी Markdown नहीं चलाता।

System 2

Unicode "Fonts" — नामों के लिए

किसी नाम को स्टाइल करने के लिए आप Discord से कुछ render करने को नहीं कह सकते — इसलिए आप ऐसे कैरेक्टर इस्तेमाल करते हैं जो पहले से स्टाइल दिखते हैं। जनरेटर "Nova" को खास Unicode कैरेक्टर से 𝗡𝗼𝘃𝗮 या 𝓝𝓸𝓿𝓪 में बदल देता है, और आप तैयार नतीजे को सीधे field में पेस्ट कर देते हैं। कुछ render करने की ज़रूरत नहीं, इसलिए यह वहां भी टिकता है जहां Markdown नहीं टिकता।

यह आपके display name, server nickname, server और channel नामों, role नामों, आपकी bio और messages में काम करता है। सिर्फ एक ही जगह है जहां यह रुकता है:

@username इसे रिजेक्ट करता है। आपका यूनिक handle (@ के बाद वाला lowercase नाम) सिर्फ a–z, 0–9, _ और . की अनुमति देता है — mentions, search और routing के लिए। वहां fancy font पेस्ट करें तो Discord इसे save करने से मना कर देता है। इसके बजाय अपना display name स्टाइल करें।

दो ईमानदार बातें: Unicode नाम कुछ devices (खासकर पुराने Android) पर box दिख सकते हैं, और ये screen reader के लिए मुश्किल होते हैं। सुरक्षित स्टाइल चुनें (bold, italic, small caps) और उसे सुंदर रखें — कई बड़े servers पढ़ने में मुश्किल या zalgo नामों को सख्ती से मॉडरेट करते हैं।

System 3

Nitro Display Name Styles — Paid, और आपकी सोच से ज़्यादा सीमित

Discord का paid Nitro tier, Display Name Styles देता है — यह feature 2025 के आखिर में आया: आपके display name पर असली font, color और यहां तक कि animated effects। यह आपके profile card पर बढ़िया दिखता है। पर एक पेच है जो लोगों को मुश्किल तरीके से पता चलता है:

server के अंदर आपका role color Nitro color को overwrite कर देता है, और effects हट जाते हैं — इसलिए दूसरे members आमतौर पर सिर्फ font देखते हैं, color या animation नहीं। पूरा असर मुख्य रूप से आपके profile पर दिखता है, member list या chat में नहीं।

फ्री account menu खोलकर किसी style का preview देख सकते हैं, पर उसे save करना सिर्फ Nitro में होता है — यही preview-फिर-paywall वजह है कि अब इतने लोग पूछते हैं कि fonts के लिए Nitro ज़रूरी है या नहीं। यह इस खास feature को लेकर जायज़ सवाल है; यह Unicode styling में कोई बदलाव नहीं, जो चाहे जो हो फ्री ही रहती है।

तो Nitro तब सही है जब आपको polished profile card और हर जगह एक अलग display font चाहिए। यह किसी बातचीत में colored text लाने का तरीका नहीं है — वह एक अलग tool है (अगला section)।

Color वाला सवाल

और messages में colored text का क्या?

किसी message में colored text एक चौथी, और भी सीमित ट्रिक है: ANSI code blocks। आप टेक्स्ट को triple-backtick block में लपेटते हैं जिस पर ansi tag होता है, और color के लिए escape codes जोड़ते हैं। इसकी सीमाओं को साफ नज़र से देखें:

  • सिर्फ आठ तय colors — कोई custom hex नहीं।
  • सिर्फ code-block में — यह किसी आम वाक्य को inline color नहीं कर सकता।
  • mobile पर भरोसे लायक नहीं — phone users को अक्सर plain text दिखता है।

desktop-first server की warnings या logs के लिए काम का; आम styling tool नहीं। अगर आपके आधे members mobile पर हैं, तो मान लें कि उन्हें color नहीं दिखेगा।

FAQ

अक्सर पूछे जाने वाले सवाल

क्योंकि दोनों अलग system इस्तेमाल करते हैं। chat में **bold** Markdown है — Discord इसे तब render करता है जब आपका message दिखाता है। नाम (username, nickname, server, channel, role) Markdown नहीं चलाते, इसलिए asterisks वैसे के वैसे दिख जाते हैं। नाम स्टाइल करने के लिए आपको Unicode "fonts" चाहिए — ऐसे खास कैरेक्टर जो पहले से bold दिखते हैं — जिन्हें सीधे field में पेस्ट करते हैं।

नहीं। Unicode "fonts" फ्री substitute कैरेक्टर हैं जिन्हें आप कहीं भी पेस्ट कर सकते हैं जहां नाम अनुमत है; ये सबके लिए काम करते हैं पर कुछ devices पर box के रूप में दिख सकते हैं और screen reader तोड़ देते हैं। Nitro Display Name Styles एक paid feature है जो आपके display name पर असली font, color और effects लगाती है — पर color और effects servers के अंदर नहीं दिखते, जहां आपका role color जीतता है; सिर्फ font ही आगे जाता है।

ANSI code blocks से: अपने टेक्स्ट को triple-backtick block में लपेटें जिस पर ansi tag हो, और color के लिए escape codes जोड़ें। यह सिर्फ आठ तय colors तक सीमित है, सिर्फ code blocks के अंदर काम करता है, और mobile पर भरोसे लायक नहीं (अक्सर plain text दिखता है)। यह messages के लिए है, नामों के लिए नहीं।

दो आम वजहें: asterisks और शब्द के बीच space है (** text ** bold नहीं होगा — **text** होगा), या टेक्स्ट code block के अंदर है (backticks Markdown बंद कर देते हैं)। और याद रखें Markdown सिर्फ messages में काम करता है, नामों में कभी नहीं।
