디스코드 텍스트 서식, 해부하기

여러분에게는 '폰트' 문제가 있는 게 아니라 — '세 가지 시스템' 문제가 있는 것입니다. 디스코드는 마크다운, 유니코드 문자, 니트로 스타일을 완전히 다른 용도로 씁니다. 어떤 칸이 어떤 시스템을 쓰는지만 알면, 모든 '이게 왜 안 되지?'가 스스로 답합니다.

플랫폼 마스터리 ⏱ 8분 분량 세 시스템 모델

핵심 요약

  • 디스코드에는 서로 무관한 세 가지 텍스트 시스템이 있습니다: 마크다운(메시지), 유니코드 '폰트'(모든 이름 칸), 그리고 니트로(유료 표시 이름 스타일).
  • **볼드** 같은 마크다운은 메시지에서만 렌더링됩니다 — 사용자명, 별명, 서버·채널 이름에서는 절대 작동하지 않습니다.
  • 유니코드 '폰트'는 모든 이름 칸에서 작동하지만, 일부 기기에서 네모로 보이고 스크린 리더를 깨뜨릴 수 있습니다.
  • 니트로는 표시 이름에 실제 색상과 효과를 더합니다 — 하지만 서버 안에서는 역할 색상이 우선되어 폰트만 표시됩니다.
관점 바꾸기

폰트가 문제가 아니라 — 세 가지 다른 시스템입니다

디스코드의 '텍스트가 왜 안 되지' 질문은 거의 다 서로 아무 관련 없는 세 가지를 뭉뚱그리는 데서 나옵니다. 디스코드는 채팅에서 마크다운을 가르쳐 주기 때문에, 같은 방법으로 이름도 꾸밀 수 있으리라 생각하게 됩니다. 하지만 안 됩니다 — 이름은 완전히 다른 시스템으로 돌아갑니다.

전체 지형을 한 틀에 담았습니다. 각 칸이 어떤 시스템을 쓰는지 익히면 다시는 당황할 일이 없습니다.

시스템정체작동 위치함정
마크다운디스코드가 렌더링하는 기호(**볼드**, *이탤릭*, ~~취소선~~, ANSI 색상)메시지 전용모든 이름 칸에서 무효; ANSI 색상은 PC 전용
유니코드 '폰트'이미 꾸며진 모습의 대체 문자(𝗯𝗼𝗹𝗱, 𝓬𝓾𝓻𝓼𝓲𝓿𝓮)표시 이름, 별명, 서버·채널·역할 이름, 자기소개, 메시지네모로 보일 수 있음; 스크린 리더를 깨뜨림; @사용자명에서는 거부됨
니트로 스타일유료 표시 이름 스타일: 실제 폰트 + 색상 + 효과표시 이름서버 안에서는 색상·효과가 안 보임(역할 색상 우선); 유료
시스템 1

마크다운 — 메시지용

마크다운은 디스코드가 메시지를 표시할 때 적용하는 서식입니다. 단어 주위에 기호를 입력하면 디스코드가 이를 실제 스타일로 바꿔 줍니다.

  • **볼드** → 볼드
  • *이탤릭* → 이탤릭
  • ~~취소선~~ → 취소선
  • __밑줄__ → 밑줄
  • ||스포일러|| → 클릭 전까지 숨김
  • > 인용과 `코드`

이것이 메시지를 서식화하는 올바른 방법입니다 — 실제 텍스트로 남으므로 검색되고 접근성도 좋습니다. 함정은 이것을 '안 되게' 만드는 두 가지 실수입니다:

볼드 안 됨

** 텍스트 ** — 별표 안쪽의 공백이 취소시킵니다. **텍스트**를 쓰세요.

볼드 안 됨

`코드 블록` 안에서는 백틱이 마크다운을 끕니다. 스타일을 블록 밖으로 옮기세요.

그리고 결정적으로: 마크다운은 사용자명, 별명, 서버 이름, 채널 이름에서는 아무것도 하지 않습니다. 그것들은 메시지가 아니므로, 디스코드가 절대 마크다운을 실행하지 않습니다.

시스템 2

유니코드 '폰트' — 이름용

이름을 꾸미려면 디스코드에게 무언가를 렌더링해 달라고 요청할 수 없으므로 — 이미 꾸며진 모습의 문자를 씁니다. 생성기는 특수한 유니코드 문자를 이용해 'Nova'를 𝗡𝗼𝘃𝗮나 𝓝𝓸𝓿𝓪로 바꿔 주고, 여러분은 완성된 결과를 칸에 그대로 붙여넣습니다. 렌더링이 필요 없으므로 마크다운이 통하지 않는 곳에서도 살아남습니다.

이 방식은 표시 이름, 서버 별명, 서버·채널 이름, 역할 이름, 자기소개, 메시지에서 작동합니다. 막히는 곳은 딱 한 군데입니다:

@사용자명은 거부합니다. 여러분의 고유 아이디(@ 뒤의 소문자)는 멘션·검색·라우팅을 위해 a–z, 0–9, _, .만 허용합니다. 화려한 폰트를 거기 붙여넣으면 디스코드는 저장을 거부합니다. 대신 표시 이름을 꾸미세요.

솔직한 두 가지 유의점이며, 둘 다 다른 곳에서 자세히 다룹니다: 유니코드 이름은 일부 기기(특히 구형 안드로이드)에서 네모로 보일 수 있고, 스크린 리더가 읽기 어렵습니다. 안전한 스타일(볼드, 이탤릭, 스몰캡스)을 골라 세련되게 유지하세요 — 많은 대형 서버가 읽기 어렵거나 잘고 이름을 강하게 제재합니다.

시스템 3

니트로 표시 이름 스타일 — 유료, 그리고 생각보다 좁음

디스코드의 유료 니트로 등급은 2025년 말에 추가된 표시 이름 스타일 기능을 제공합니다: 실제 폰트, 색상, 심지어 움직이는 효과까지 표시 이름에 적용됩니다. 프로필 카드에서는 멋져 보입니다. 하지만 사람들이 뒤늦게 깨닫는 함정이 있습니다:

서버 안에서는 역할 색상이 니트로 색상을 덮어쓰고 효과는 벗겨집니다 — 그래서 다른 멤버에게는 대개 색상이나 애니메이션이 아니라 폰트만 보입니다. 완전한 효과는 주로 프로필에서 나타나고, 멤버 목록이나 채팅에서는 아닙니다.

무료 계정도 메뉴를 열어 스타일을 미리 볼 수 있지만, 저장은 니트로 전용입니다 — 이 '미리보기 후 결제 유도'가 바로 많은 사람이 폰트에 니트로가 꼭 필요한지 묻게 된 이유입니다. 이 특정 기능에 대해서는 타당한 질문이지만, 유니코드 꾸미기가 바뀐 것은 아닙니다. 유니코드 꾸미기는 여전히 무료입니다.

그러니 니트로는 세련된 프로필 카드와 어디서나 뚜렷한 표시 폰트를 원한다면 값어치가 있습니다. 대화에 색깔 있는 글자를 넣는 방법은 아닙니다 — 그건 다른 도구입니다(다음 섹션).

색상 문제

메시지 안의 색깔 있는 글자는요?

메시지 안의 색깔 있는 글자는 네 번째의, 더 좁은 기법입니다: ANSI 코드 블록. 텍스트를 백틱 세 개 블록으로 감싸고 ansi 태그를 붙인 뒤 색상 이스케이프 코드를 추가합니다. 한계를 분명히 알아 두세요:

  • 고정된 여덟 가지 색상만 — 커스텀 hex 불가.
  • 코드 블록 전용 — 일반 문장에 인라인으로 색을 넣을 수 없음.
  • 모바일에서 불안정 — 휴대폰 사용자에게는 일반 텍스트로 보이는 경우가 잦음.

PC 우선 서버의 경고나 로그에는 유용하지만, 범용 꾸미기 도구는 아닙니다. 멤버 절반이 모바일이라면, 그들은 색을 못 본다고 가정하세요.

FAQ

자주 묻는 질문

서로 다른 시스템을 쓰기 때문입니다. 채팅에서 **볼드**는 마크다운이며 — 디스코드가 메시지를 표시할 때 이를 렌더링합니다. 이름(사용자명, 별명, 서버, 채널, 역할)은 마크다운을 실행하지 않으므로 별표가 그대로 보일 뿐입니다. 이름을 꾸미려면 이미 볼드처럼 보이는 특수 문자인 유니코드 '폰트'를 칸에 직접 붙여넣어야 합니다.

아니요. 유니코드 '폰트'는 이름을 넣을 수 있는 곳이면 어디에나 붙여넣을 수 있는 무료 대체 문자입니다. 누구에게나 작동하지만 일부 기기에서 네모로 보이거나 스크린 리더를 깨뜨릴 수 있습니다. 니트로 표시 이름 스타일은 실제 폰트·색상·효과를 표시 이름에 적용하는 유료 기능입니다 — 다만 서버 안에서는 색상과 효과가 나타나지 않고 역할 색상이 우선되며, 폰트만 넘어옵니다.

ANSI 코드 블록을 씁니다: 텍스트를 백틱 세 개로 감싼 블록에 'ansi' 태그를 붙이고 색상 이스케이프 코드를 추가합니다. 고정된 여덟 가지 색상으로 제한되고, 코드 블록 안에서만 작동하며, 모바일에서는 불안정합니다(일반 텍스트로 보이는 경우가 많습니다). 메시지용이지 이름용이 아닙니다.

흔한 두 가지 이유가 있습니다: 별표와 단어 사이에 공백이 있거나(** 텍스트 **는 볼드가 안 되고 **텍스트**는 됩니다), 텍스트가 코드 블록 안에 있는 경우입니다(백틱은 마크다운을 끕니다). 또한 마크다운은 메시지에서만 작동하고 이름에서는 절대 작동하지 않는다는 점도 기억하세요.
