ฟอนต์สวยๆ ใช้ได้ตรงไหนบ้างใน Discord

"ชื่อผู้ใช้ไม่ถูกต้อง" ชื่อช่องที่เสียตัวพิมพ์ใหญ่ไป ชื่อเล่นที่บันทึกได้สบายๆ Discord ไม่ได้เอาแน่เอานอนไม่ได้ — ทุกช่องมีหน้าที่ของมัน และแต่ละช่องบังคับใช้กฎต่างกัน นี่คือแผนที่สิทธิ์การใช้งานทั้งหมด เพื่อให้คุณไม่ต้องเดาอีกต่อไป

แพลตฟอร์ม: Discord ⏱ อ่าน 9 นาที เมทริกซ์สิทธิ์แบบช่องต่อช่อง

ประเด็นสำคัญ

  • ชื่อผู้ใช้ @ ที่ไม่ซ้ำใครรับเฉพาะตัวพิมพ์เล็ก a–z, 0–9, ขีดล่าง และจุด วางฟอนต์สวยๆ ลงไปแล้วคุณจะได้ "ชื่อผู้ใช้ไม่ถูกต้อง" — ทุกครั้ง เพราะออกแบบมาแบบนั้น
  • ทุกช่องการแสดงผล — ชื่อที่แสดง ชื่อเล่นในเซิร์ฟเวอร์ บทบาท ชื่อเซิร์ฟเวอร์และช่อง เกี่ยวกับฉัน — รับฟอนต์ Unicode และอิโมจิได้โดยไม่ต้องมีลูกเล่นอะไร
  • Markdown แสดงผลเฉพาะในข้อความแชต (บวกพื้นฐานในส่วนเกี่ยวกับฉัน) ในทุกช่องชื่อ ดอกจันจะแค่นั่งอยู่เฉยๆ
  • ชื่อที่ตกแต่งมีต้นทุนจริง: Ctrl+K หา 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 ด้วยการพิมพ์ "aesthetic" ไม่เจอ โปรแกรมอ่านหน้าจอสะดุด และ Android รุ่นเก่าอาจแสดงเป็นกล่อง
แนวคิดหลัก

Discord ไม่ได้เอาแน่เอานอนไม่ได้ — แต่ละช่องมีหน้าที่ของมัน

วงจรลองผิดลองถูกมักเป็นแบบนี้: คุณตกแต่งชื่อด้วยตัวสร้าง วางลงในช่อง Discord ช่องหนึ่งแล้วมันบันทึกได้สวยงาม พอวางข้อความเดียวกันลงในอีกช่องหนึ่ง Discord กลับปฏิเสธหน้าตาเฉย อักขระเดียวกัน บัญชีเดียวกัน ผลตรงข้ามกัน มัน รู้สึก เหมือนไม่มีเหตุผล

แต่มันไม่ใช่ ช่องต่างๆ ของ Discord แบ่งออกเป็นสองตระกูลอย่างชัดเจน ช่องตัวตน คือช่องที่ระบบอื่นต้องพึ่งพา — การกล่าวถึง คำขอเป็นเพื่อน บันทึกการดูแล การกู้คืนบัญชี มีอยู่ช่องเดียวเป๊ะๆ: ชื่อผู้ใช้ @ ที่ไม่ซ้ำใครของคุณ ซึ่งถูกล็อกไว้ที่ชุดอักขระเล็กจิ๋วเพื่อให้มันปลอมไม่ได้ พิมพ์ผิดไม่ได้ และไม่แสดงต่างกันบนแต่ละโทรศัพท์ ช่องการแสดงผล คือทุกสิ่งที่คน มอง — ชื่อที่แสดง ชื่อเล่น ชื่อบทบาท ชื่อเซิร์ฟเวอร์และช่อง เกี่ยวกับฉัน ช่องเหล่านั้นเปิดกว้าง เพราะไม่มีอะไรสำคัญวิ่งผ่านมัน

พอคุณเห็นสองตระกูลนี้แล้ว ทุกคำถาม "ทำไมอันนี้บันทึกไม่ได้?" จะตอบตัวมันเอง คุณไม่เคยสู้กับบั๊ก คุณแค่วางอักขระระดับการแสดงผลลงในช่องระดับตัวตน วิธีแก้เหมือนเดิมเสมอ: ย้ายการตกแต่งไปอีกช่องหนึ่ง

กับดักอันดับ 1

ชื่อผู้ใช้ vs ชื่อที่แสดง: ที่มาของ "ชื่อผู้ใช้ไม่ถูกต้อง"

ความสับสนอันเดียวนี้สร้างความพยายามที่ล้มเหลวมากกว่าทุกอย่างอื่นรวมกัน ตั้งแต่ Discord เลิกใช้ตัวเลขสี่หลักแบบเก่า ทุกบัญชีมีชื่อ สอง ชื่อ และมันตามกฎที่ตรงกันข้าม:

  • ชื่อผู้ใช้ — handle ที่ไม่ซ้ำใครของคุณ แสดงด้วย @ ในโปรไฟล์ อักขระที่อนุญาต: ตัวพิมพ์เล็ก a–z, 0–9, _ และ . — ไม่มีอย่างอื่น ไม่ใช่ตัวพิมพ์ใหญ่ ไม่ใช่เว้นวรรค และแน่นอนว่าไม่ใช่ 𝓬𝓾𝓻𝓼𝓲𝓿𝓮 อะไรที่หลุดจากชุดนี้จะทำให้เกิดข้อผิดพลาด "ชื่อผู้ใช้ไม่ถูกต้อง"
  • ชื่อที่แสดง — ชื่อตัวใหญ่เป็นมิตรที่โชว์ในแชตและบนโปรไฟล์ มันรับเว้นวรรค ตัวพิมพ์ใหญ่ อิโมจิ และอักขระฟอนต์ Unicode ทุกตัวที่คุณวางได้

ดังนั้นรูปแบบที่ได้ผลคือ ข้างในธรรมดาแต่ข้างนอกตกแต่ง:

ถูกปฏิเสธ @𝕹𝖔𝖛𝖆 → "ชื่อผู้ใช้ไม่ถูกต้อง" ↓ ได้ผล @nova_riot  +  ชื่อที่แสดง 𝕹𝖔𝖛𝖆 ⚔

ภายในเซิร์ฟเวอร์ คุณได้ชั้นที่สาม คือ ชื่อเล่นในเซิร์ฟเวอร์ ซึ่งทับชื่อที่แสดงของคุณเฉพาะเซิร์ฟเวอร์นั้น — และมันก็ยืดหยุ่นพอๆ กัน ตกแต่งให้ต่างกันตามแต่ละคอมมูนิตี้: ୨୧ 𝒩𝑜𝓋𝒶 ୨୧ ในชมรมอ่านหนังสือ, 𝗡𝗢𝗩𝗔 ในเซิร์ฟเวอร์อีสปอร์ต ตัวสร้างชื่อเล่นจะจัดการการแปลงอักขระให้คุณเอง

กรอบคิด

เมทริกซ์สิทธิ์การใช้งานแบบช่องต่อช่อง

นี่คือแผนที่ทั้งหมด — ทุกช่องข้อความใน Discord แต่ละช่องรับอะไร และ ทำไม บุ๊กมาร์กตารางนี้ไว้ แล้วการเดาก็จบ

อ่านคอลัมน์จากบนลงล่างแล้วตรรกะจะโดดออกมา: มีแถวเดียวเป๊ะๆ ที่ปฏิเสธ Unicode และมีแถวเดียวเป๊ะๆ ที่รัน Markdown เต็มรูปแบบ ทุกอย่างระหว่างนั้นคือช่วงกลางที่เปิดกว้าง — สไตล์แบบวางลงไปยินดีต้อนรับ สไตล์แบบแสดงผลถูกเมิน นั่นคือทั้งระบบ

บันทึกภาคสนาม

อาการของชื่อช่อง: ตัวพิมพ์เล็กอัตโนมัติ ขีดกลางอัตโนมัติ

ชื่อช่องข้อความถูกเขียนใหม่เงียบๆ ตอนบันทึก: ตัวพิมพ์ใหญ่ปกติถูกแปลงเป็นตัวพิมพ์เล็กและเว้นวรรคกลายเป็นขีดกลาง จึงเป็นเหตุผลที่ General Chat ออกมาเป็น #general-chat คนอ่านว่า "Discord ลบสไตล์ของฉัน" ลองดูให้ชัดๆ — มันแตะเฉพาะตัวอักษรธรรมดาเท่านั้น

พิมพ์: GENERAL CHAT → บันทึกเป็น #general-chat  ·  พิมพ์: 𝗚𝗘𝗡𝗘𝗥𝗔𝗟 ✦ 𝗖𝗛𝗔𝗧 → บันทึกเป็น #𝗚𝗘𝗡𝗘𝗥𝗔𝗟-✦-𝗖𝗛𝗔𝗧

𝗚 คณิตศาสตร์ตัวหนาไม่ใช่ตัว G พิมพ์ใหญ่ธรรมดา — มันเป็นอักขระ Unicode คนละตัว — กฎการแปลงเป็นตัวพิมพ์เล็กจึงข้ามมันไป นั่นแหละคือช่องโหว่ที่อยู่เบื้องหลังทุกเซิร์ฟเวอร์ที่คุณเคยเห็นซึ่งมีรายการช่องเป็นตัวพิมพ์ใหญ่และตกแต่งสวยงาม สองเชิงอรรถ: ช่องเสียงและหมวดหมู่ไม่ถูกทำให้เป็นมาตรฐานเลย (เว้นวรรคและตัวพิมพ์ใหญ่ธรรมดาอยู่รอดตรงนั้น) และหัวข้อหมวดหมู่คือที่ที่ตัวคั่นสัญลักษณ์อย่าง ─── และ ╭─ ทำงานได้ดีที่สุด

สไตล์แบบแสดงผล

Markdown ทำงานตรงไหน — และตรงไหนที่มันแค่นั่งอยู่เฉยๆ

Markdown คือสไตล์อีกชนิดหนึ่ง: สัญลักษณ์อย่าง **bold** ที่ Discord แปลงตอนมัน แสดงผล ข้อความ เมทริกซ์แสดงว่าอาณาเขตของมันเล็กจิ๋ว — ข้อความแชต บวกการจัดรูปแบบพื้นฐานในส่วนเกี่ยวกับฉัน พิมพ์ **Nova** ลงในช่องชื่อเล่นแล้วดอกจันจะบันทึกเป็นอักขระตรงๆ เพราะช่องชื่อถูกเก็บและแสดงแบบดิบๆ ไม่มีการแสดงผลรอบใดมาแปลงมัน

นี่คือการแบ่งที่ต้องจำในทางปฏิบัติ: สไตล์แบบแสดงผล (Markdown) สำหรับสิ่งที่คุณพูด สไตล์แบบวางลงไป (Unicode) สำหรับสิ่งที่ใช้เรียกคุณ กลไกเต็มๆ — แท็กสปอยเลอร์ บล็อกโค้ด ชั้น Nitro และข้อผิดพลาดคลาสสิก "ทำไมดอกจันของฉันไม่เป็นตัวหนา" — อยู่ในคู่มือคู่กันของเรา ถอดรหัสการจัดรูปแบบข้อความ Discord

มีกรณีพิเศษหนึ่งที่ควรชี้: ข้อความสี มันมีอยู่เฉพาะภายในข้อความแชตเท่านั้น เฉพาะผ่านบล็อกโค้ด ANSI มีแปดสีตายตัวและการรองรับบนมือถือที่ไม่แน่นอน ไม่มีช่องชื่อไหนใน Discord ที่รับสี

ข้อจำกัดตามจริง

เมื่อไหร่ที่คุณไม่ควรตกแต่งช่อง (แม้จะทำได้)

"รับ Unicode ได้" เป็นการอนุญาต ไม่ใช่คำแนะนำ ชื่อที่ตกแต่งมาพร้อมต้นทุนสามอย่าง และควรชั่งน้ำหนักก่อนตัดสินใจ:

การค้นหาพัง

Ctrl+K การค้นหาสมาชิก และการเติมชื่ออัตโนมัติของการกล่าวถึง จับคู่กับอักขระตามตัวอักษร การพิมพ์ "aesthetic" จะไม่มีวันหา 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 เจอ — มันไม่มีอักขระร่วมกันเลย

โปรแกรมอ่านหน้าจอสะดุด

เทคโนโลยีช่วยเหลืออาจอ่าน 𝕹𝖔𝖛𝖆 ว่า "อักษรตัวใหญ่ fraktur ทางคณิตศาสตร์ N…" หรือข้ามมันไปเลย

กล่องบน Android รุ่นเก่า

สไตล์วิจิตรอาจแสดงเป็น □□□□ บนเครื่องรุ่นเก่า ในกรณีที่ความอ่านง่ายสำคัญ ให้เลือกสไตล์ที่เรียบ

กฎของผม: ตกแต่งช่องที่คนมอง เก็บช่องที่คนพิมพ์ให้เรียบ ชื่อที่แสดงและหัวข้อหมวดหมู่? ตกแต่งได้เต็มที่ — ตัวหนา small caps และสัญลักษณ์เบาๆ อ่านออกได้ดีเกือบทุกที่ ช่องข้อความที่คึกคักซึ่งสมาชิกค้นหาทุกวัน บทบาทที่โมดปิงตลอด ชื่อเซิร์ฟเวอร์ที่คุณอยากให้ค้นเจอ? เก็บพวกนั้นให้เรียบหรือเกือบเรียบ และเลี่ยง Zalgo ในชื่อไปเลย — เซิร์ฟเวอร์ใหญ่หลายแห่งดูแลลบมันอัตโนมัติ และมันเป็นสไตล์ที่มีโอกาสทำให้การแสดงผลพังมากที่สุด

เพราะชื่อผู้ใช้ @ ที่ไม่ซ้ำใครเป็นกุญแจของตัวตน ไม่ใช่ช่องสำหรับการแสดงผล มันรับเฉพาะตัวพิมพ์เล็ก a–z, 0–9, ขีดล่าง และจุด — การวางอักขระฟอนต์ Unicode (หรือแม้แต่ตัวพิมพ์ใหญ่ปกติ) จึงทำให้ Discord ปฏิเสธการบันทึก เอาเวอร์ชันที่ตกแต่งไปใส่ในชื่อที่แสดงหรือชื่อเล่นในเซิร์ฟเวอร์แทน ช่องเหล่านั้นรับ Unicode ได้เต็มที่

ได้ ชื่อที่แสดง ชื่อเล่นในเซิร์ฟเวอร์ ชื่อบทบาท ชื่อเซิร์ฟเวอร์ ชื่อช่อง และส่วนเกี่ยวกับฉันของคุณ ล้วนรับอักขระฟอนต์ Unicode และอิโมจิได้ สร้างข้อความที่ตกแต่งแล้ววางอักขระสำเร็จลงในช่อง — ไม่มีอะไรต้องเปิดใช้ ควรเลือกสไตล์ที่อ่านง่ายอย่างตัวหนา ตัวเอียง หรือ small caps เพื่อให้สมาชิกบนเครื่องรุ่นเก่าและโปรแกรมอ่านหน้าจอยังอ่านคุณได้

ชื่อช่องข้อความถูกทำให้เป็นมาตรฐาน: Discord แปลง A–Z ปกติเป็นตัวพิมพ์เล็กและเปลี่ยนเว้นวรรคเป็นขีดกลาง ดังนั้น "General Chat" จึงกลายเป็น "general-chat" อักขระฟอนต์ Unicode ไม่ใช่ตัวอักษรปกติ จึงผ่านไปโดยไม่ถูกแตะต้อง — 𝗚𝗘𝗡𝗘𝗥𝗔𝗟 ยังเก็บตัวพิมพ์ใหญ่ไว้เพราะมันเป็นอักขระคณิตศาสตร์ตัวหนา ไม่ใช่ A–Z ชื่อช่องเสียงและหมวดหมู่ข้ามการทำให้เป็นมาตรฐานนี้และเก็บเว้นวรรคกับตัวพิมพ์ใหญ่ไว้

ได้ ทั้งสองเป็นช่องการแสดงผล ฟอนต์ Unicode สัญลักษณ์ และอิโมจิจึงบันทึกได้โดยไม่มีปัญหา และบทบาทที่ตกแต่งซึ่งแยกแสดง (hoisted) จะโผล่ในแถบรายชื่อสมาชิก สิ่งที่ต้องแลก: การค้นหา การเติมชื่ออัตโนมัติของการกล่าวถึง และบอตดูแลเซิร์ฟเวอร์จำนวนมากจับคู่กับอักขระตามตัวอักษร ชื่อบทบาทที่ตกแต่งจัดจึงหาและพิมพ์ได้ยากกว่า

ได้ — การกล่าวถึงจะอ้างอิงกับบัญชีของคุณ ไม่ใช่อักขระที่ตกแต่ง การพิมพ์ชื่อผู้ใช้ @ ธรรมดาของคุณจะหาคุณเจอเสมอ และการคลิกชื่อคุณหรือเลือกคุณจากรายชื่อสมาชิกก็ใช้ได้ สิ่งที่พังคือการเติมชื่ออัตโนมัติด้วยชื่อที่แสดง: การพิมพ์ "aesthetic" จะไม่ตรงกับ 𝕬𝖊𝖘𝖙𝖍𝖊𝖙𝖎𝖈 เพราะมันเป็นอักขระคนละตัว นั่นแหละคือเหตุผลที่ Discord เก็บ handle ให้เป็นข้อความธรรมดา: มันคือวิธีที่รับประกันว่าจะติดต่อคุณได้
